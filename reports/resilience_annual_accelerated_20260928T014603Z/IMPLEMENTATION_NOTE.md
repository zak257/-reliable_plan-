# 全年8760小时规划的加速实施

本轮保留8760小时逐时规划、四个72小时韧性窗口、核心零失供、常规损失计费、灵活性负荷时限、UPS应急专用、实际非零有功构网和日前信息约束。七类容量始终按既有整数模块规划，不作事后取整。

设备故障恢复采用最新设置：柴发运行故障、启动失败维修、PCS、UPS及新能源母线均为12小时，主母线失电1小时；UPS容量桥接要求为12小时。经济性仍为一次性投资加全年期望运行和失供费用，EENS上限100 kWh、95% CVaR上限1000 kWh。

## 1. 已实施的等价压缩

1. **合并完全重复的场景。** 比较全部负荷、天气、日前信息、设备可用性、原始故障触发集合和恢复时长；仅名称、权重不参与比较。相同场景保留一组运行变量并累加权重。每个窗口16条记录合并为14条，全年64条记录合并为56条，独立调度块由61个降为53个。原标签通过`scenario_aliases.json`保留。
2. **复用确定常数。** 不可能被触发的运行故障、启动失败及维修状态直接引用固定零变量；未获应急许可的UPS放电、正常时段不需要的UPS补电等也按可证明条件固定。核心负荷为正且UPS不可用时，主母线带电状态由功率平衡推得，无需重复设置自由变量。所有值仍可逐时审计和导出。
3. **减少静态非预见性等式。** 对同一小时必然共享信息的场景，采用连接所有成员的生成树等式，取代两两等式。柴油机故障是否被观察到取决于实际运行或启动尝试，这部分仍保留动态条件约束，没有按隐藏故障标签提前分开调度。
4. **收紧有效容量上界。** 在经济搜索区域内，扣除UPS最低必要投资后计算各类模块的有效上界。没有人为指定机组数量上限，也没有删去可能更优的容量点。

以上均不采用代表日替代全年，也不放松供电与信息约束。求解器本身也会预处理一部分冗余，因此变量减少比例不直接等于求解加速比例。

## 2. 全年初始可行方案

初始化参考已审计168小时解的风光配置，并依据全年峰值负荷、启动准备和期初电池可用能量生成整数候选。采用逐台准备、成功启动后维持可用机组在线的因果策略。运行故障只能在实际在线时触发，维修后仍需满足人员可达、准备和温度条件。

初始候选单独建立完整8760小时和全部压缩分支模型，临时固定容量与上述启停策略，并限制平移任务原小时完成。期初用电池桥接启动过程，随后补回库存。连续出力、加热、合法中断与充电等仍由原功率和能量约束确定。主母线失电对应的常规负荷损失完整计入。

这组额外限制只用于快速构造初始方案。只有同时通过完整功率、能量、温度、窗口连接、信息、任务及风险审计的方案，才会被保存并传入正式模型。如果该策略求解失败，只说明该初始化没有成功，不能据此宣称原规划模型不可行。

正式模型重新建立并放开所有容量与运行变量。传递初始解的数值，不传递临时固定约束；新出现的未安装柴油机槽位赋零启停和零出力，其正常轨迹温度按无加热的热模型填入。

## 3. 全局搜索区域和上下界

设经过全年审计的初始方案总费用为$U$。所有费用项非负，因此任何优于它的方案都满足：

$$
C_{inv}\le U.
$$

正式模型以此建立可证明覆盖更优方案的经济搜索区域，而非由研究人员任选机组数量上下限。UPS最低必要投资用于进一步收紧单类设备数量界限。如果没有取得初始可行解，则使用可扩大的初始经济区域，不将未经认证的区域结果直接称为全局最优。

初始方案也保留为可行上界。正式模型超时时，如已经得到更好方案则保存更好方案；如未接受或改进初始方案，则保留已审计的初始方案，并明确标注其来源、正式模型下界和剩余差距。

## 4. 求解设置与计时

- 总预算15000秒，包含初始模型建立、求解、审计与导出，以及正式模型建立和求解；最终导出时间另外记录。
- 初始方案求解预算最多1200秒，计入上述总预算。
- 正式求解以1%的最优性差距为阶段目标；所有物理和风险约束保持原精度。
- 使用8线程，`MIPFocus=1`，`Heuristics=0.2`，优先获得并改善可行方案。
- 在冻结168小时输入上对`Method=1`和`Method=2`各作45秒根节点测试，保留相同初始解、相同线程和相同模型；年度运行采用验证记录中的推荐值。这是有限测试，不构成对全年速度的保证。
- 每45秒以内可用回调更新一次进度，另记录每次发现的可行目标值、建模规模、初始解传递完整度和源码哈希。

先前比较运行的原始设置与源码快照保持不变。本次引入12小时设备恢复、12小时UPS桥接和1%阶段精度，与历史年度运行参数不同，不能仅比较墙钟时间就声称算法提高若干倍。

## 5. 验证

原有物理、信息与年度连接测试在压缩版本下重复运行；增加了场景合并权重、隐藏故障不合并、压缩前后最优费用一致、固定策略审计和向自由容量模型转移初始解的检查。

另外直接使用已保存的168小时可行解检验压缩版，保留其物理和风险指标，并核对完整审计。验证记录位于[168小时压缩与根节点测试](prelaunch_verification/verification.json)。

本次没有加入Benders分解或按周独立代替全年。后续只有在压缩与热启动仍不足时，再评估更大范围的分解改造。

## 6. 入口与产物

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 /home/yzk/cap_plan/venv/bin/python \
  -m scripts.run_resilience_annual_accelerated \
  --output reports/resilience_annual_accelerated_NEW_RUN \
  --time-limit-seconds 15000 --seed-seconds 1200 \
  --threads 8 --method 1 --mip-gap 0.01
```

`--method`以本轮验证记录为准。核心文件：

| 文件 | 内容 |
|---|---|
| `run_definition.json` | 冻结输入、恢复参数、模块、时间预算、源码哈希 |
| `run_status.json`、`progress.json`、`events.jsonl` | 进程状态和分阶段进度 |
| `seed/summary.json`、`seed/solution.sol` | 已审计的完整年度初始方案 |
| `economic_bound.json` | 经济搜索区域的来源和覆盖性依据 |
| `warm_start_transfer.json` | 初始解匹配、补齐和缺失变量统计 |
| `model_statistics.json` | 正式模型规模和整数容量类型 |
| `gurobi.log` | 正式优化日志 |
| `summary.json`、`RESULT_REPORT.md` | 最终可行方案、上下界、差距和耗时 |
| `hourly_dispatch.csv`、`dispatch.npz` | 正常全年轨迹及韧性分支实际运行 |

代码入口：[年度运行脚本](../../scripts/run_resilience_annual_accelerated.py)、[压缩及热启动工具](../../polar_reliability_planning/resilience_milp/acceleration.py)。
