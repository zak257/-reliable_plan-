# 全年MILP延长求解

本轮按用户最新要求沿用原模型，不增加柴油用量上限或新能源占比下限，不调整成本参数。主时域仍为8760小时，联合四个72小时韧性窗口，全部设备采用原整数模块，正式规划的七类容量全部自由。

新增预算60000秒（16小时40分），包括初始解改进、重新建模、求解与审计，最终导出可能有少量尾差。目标最优性差距为1%，延长时限不构成达到此精度的保证。

## 保存内容的复用

上一轮有完整可行解和有效全局下界，但没有可恢复的搜索树或单纯形状态。因此本次复用容量、运行策略及逐时可行解，重新启动Gurobi搜索，不能称为恢复原搜索节点或迭代位置。

运行前比较原源码快照与当前物理建模代码，并校验输入文件哈希。只允许年度结果序列化部分存在差异。原下界只在这一核对通过、配置保持一致时复用；它与新自由模型下界取较大值。临时限制模型产生的下界不用于全局最优性证明。

## 初始可行解改进

1. 最多300秒：保留旧方案的柴油机数量、运行与故障观察策略及电池充放电模式，释放风光、电池、PCS、UPS整数容量以及柔性任务服务时间。容量直接由MILP确定，不枚举候选表，也不事后取整。
2. 最多600秒：进一步放开普通电池全年各小时的充放电模式，保留原模型的SOC、功率、构网及场景信息约束，改善储能利用。
3. 将通过完整年度审计的最好方案传入重新建立的自由联合MILP。正式模型没有上述临时固定限制，柴油机数量和启停也重新自由优化。

这些临时限制用于尽快构造更好的初始解。如未改善，则仍保留上一轮已审计的可行解。改善阶段会准确展开控制量已经固定的指示约束；仍需优化的电池模式指示约束保留。

正式求解使用Gurobi原生并发LP方法处理根节点（`Method=3`），8线程，`MIPFocus=1`，`Heuristics=0.2`。此前根节点占时较多，本次允许原生并发方法竞争处理根松弛；不改变MILP的物理或经济约束。

## 输出与检查

- `capacity_polish/`、`storage_polish/`：只有改善且通过完整年度审计后才保存的初始方案。
- `checkpoints/`：Gurobi自动写出的整数候选解；它们在完整审计前不作为正式结果。
- `progress.json`、`events.jsonl`：当前阶段、候选费用、上下界与进度。
- `summary.json`、`RESULT_REPORT.md`：结束后保存的正式结果。
- `run_definition.json`：原运行来源、输入哈希、模型一致性检查、时间预算及源码快照。

本轮不覆盖上次结果目录。累计耗时报告为上次全流程耗时与本轮全流程耗时之和，不将中间开发与验证时间计算为求解时间。
