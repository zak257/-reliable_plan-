# 168小时规划试验：设备故障恢复12小时

本轮将主时域缩短为连续168小时，仍采用主轨迹与72小时韧性窗口相连接的模型。全部设备容量按整数模块规划；不固定任何一类设备数量，不在求解后对连续容量取整。

## 本轮设置

| 项目 | 设置 |
|---|---|
| 数据 | 上一次正式年度运行冻结输入的第792—959小时 |
| 模拟日期 | 2026年2月3日00:00至2月10日00:00，不含结束时刻，UTC+08:00 |
| 主规划时域 | 168小时，1小时时间步长 |
| 韧性窗口 | 周内第24—95小时，共72小时 |
| 日前天气信号 | 周内第24小时发布 |
| 暴风雪 | 周内第48—77小时，共30小时 |
| 主要设备故障起点 | 周内第60小时 |
| 新能源母线断开 | 正常天气和暴风雪下均持续12小时 |
| PCS、UPS故障 | 各持续12小时 |
| 柴发运行故障、启动失败维修 | 各12小时；仍仅在实际运行或启动尝试时暴露 |
| 主母线强制失电 | 按用户确认，保持1小时 |
| 分支 | 正常/风雪乘八类设备条件，共16条 |
| UPS最低桥接时长 | 同步按12小时设置，备用SOC及效率不变 |
| 风险限额 | EENS不超过100 kWh，95% CVaR上界不超过1000 kWh |
| 时间上限 | 15000秒，包含建模及计算；最终导出另外记录 |
| 模块规格 | 风光及柴发100 kW，电池50 kWh，PCS50 kW，UPS能量/功率50 kWh/50 kW |

168小时试验只衡量这一周的经济性与所设事故分支。目标为设备投资加168小时期望运行及失供费用，未把一周运行费用放大成全年费用。风险限额沿用原数值，本次报告的EENS与CVaR上界仅对应168小时，不称为年度指标。

本周核心负荷峰值为39.315922 kW，12小时桥接对应：

$$
E_U\ge\frac{39.315922\times12}{(0.95-0.05)\times0.98}
=534.910499\ \mathrm{kWh}.
$$

考虑50 kWh电量模块，最低UPS电量为550 kWh；按1.5倍核心峰值和50 kW功率模块，最低UPS功率为100 kW。这是规划约束下限，最终配置由优化决定。

主母线失电1小时导致的常规损失为223.515699 kWh，该场景两种天气分支的合计权重为0.10，因此本周不可避免的EENS部分为22.351570 kWh。若将主母线强制失电也改为12小时，这部分EENS会升至255.263987 kWh，直接超过现有100 kWh限额；本轮按已确认的1小时执行。

## 运行入口

```bash
/home/yzk/cap_plan/venv/bin/python -m scripts.run_resilience_week \
  --output reports/resilience_week_168h_repair12_run \
  --start-hour 792 --stress-start-hour 24 \
  --recovery-hours 12 --main-bus-hours 1 --ups-bridge-hours 12 \
  --time-limit-seconds 15000 --threads 4
```

程序保存冻结输入、源代码快照、每个故障的实际时段、求解日志和运行状态；结束后自动输出`summary.json`与`RESULT_REPORT.md`。如果获得完整可行解，还会保存七类设备配置、逐时运行曲线、每个韧性分支的失供与UPS使用量，以及物理和信息约束审计。

当前默认场景生成参数已统一为设备维修12小时、主母线失电1小时。历史年度对照及组会报告对应的原参数保存在各自源代码快照中，不会随本次修改重写历史结果。
