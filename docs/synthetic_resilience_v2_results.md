# 合成 Resilience-v2 全容量规划算例

> 当前模型入口已切换到[直接 Gurobi MILP 与专用应急 UPS](resilience_milp_emergency_ups_model.md)。本页仍为旧版仿真搜索结果，不能作为新模型的容量结论。

> 历史结果说明：本页保留旧版粗容量档位及旧仿真结果，不代表最新模块、失供成本和日前信息要求下的最优方案。最新修正及求解方法边界见 [修正记录](resilience_v2_fine_modules_revision.md)。当前新增仿真规划器不是直接调度 MILP；此前“全局”表述仅针对其有限候选及固定规则。

本算例把新的负荷分层和 UPS 容量规划要求单独实现为 `resilience-v2-synthetic`。它不覆盖原 Recovery-v1，也不使用中山现场负荷作为新模型的校准数据。

这次运行已经把风电、光伏、柴油机数量、普通电池、PCS、UPS 能量和 UPS 功率全部放入同一个容量搜索。原先为了演示而使用的 `2×2×2×2×2×2×2=128` 个固定组合已经取消。这个数字的含义只是“7 个变量各取 2 个值”的笛卡尔积，并不代表机组数量的物理范围，也不适合当前的全容量规划。

## 运行方式

```bash
/home/yzk/cap_plan/venv/bin/python -m scripts.run_resilience_v2 \
  --output reports/synthetic_resilience_v2_global_discrete_16 \
  --time-limit-seconds 10000 \
  --training-scenarios 4 \
  --validation-scenarios 32
```

输出位于 [reports/synthetic_resilience_v2_global_discrete_16](../reports/synthetic_resilience_v2_global_discrete_16/)：

- [synthetic_resilience_year.csv](../reports/synthetic_resilience_v2_global_discrete_16/synthetic_resilience_year.csv)：8760 小时的合成数据；
- [capacity_evaluations.csv](../reports/synthetic_resilience_v2_global_discrete_16/capacity_evaluations.csv)：全容量组合评价；
- [scenario_fault_events.csv](../reports/synthetic_resilience_v2_global_discrete_16/scenario_fault_events.csv)：训练/验证场景中的电网母线和新能源母线故障区间；
- [summary.json](../reports/synthetic_resilience_v2_global_discrete_16/summary.json)：规划、验证和场景分类结果；
- [selected_trace.csv](../reports/synthetic_resilience_v2_global_discrete_16/selected_trace.csv)：验证集中最坏场景的逐小时轨迹。

合成负荷包含 `core_kw`、`rigid_kw`、`flex_interruptible_kw` 和 `flex_shiftable_kw` 四列。核心负荷的失供硬性判定为失败；刚性常规负荷的失供计算 $EENS$ 和 $CVaR_{0.95}$；可调负荷的调整量单独记录，不计入刚性负荷的韧性指标。

## 核心负荷占比

按 8760 小时电量统计，核心负荷全年用电量约为 `297,775 kWh`，全站负荷总用电量约为 `2,023,779 kWh`，所以核心负荷占比为：

$\text{核心负荷占比}=\frac{297,775}{2,023,779}=14.71\%$。

按平均功率计算，核心负荷平均约为 `33.99 kW`，全站平均负荷约为 `231.02 kW`，得到相同的 `14.71%`。这是当前算例中最适合汇报的占比口径，因为时间步长为 `1 h`，平均功率占比与全年电量占比一致。

| 负荷类别 | 平均功率 | 全年电量 | 占总电量比例 |
|---|---:|---:|---:|
| 核心负荷 | 33.99 kW | 297,775 kWh | 14.71% |
| 刚性常规负荷 | 138.03 kW | 1,209,128 kWh | 59.75% |
| 可中断负荷 | 33.00 kW | 289,116 kWh | 14.29% |
| 可平移负荷 | 26.00 kW | 227,760 kWh | 11.25% |
| 合计 | 231.02 kW | 2,023,779 kWh | 100.00% |

核心负荷的单小时占比随负荷曲线变化，大约在 `12.66%–17.33%` 之间。核心负荷峰值约为 `39.46 kW`，全站总负荷峰值约为 `270.46 kW`；两者各自峰值的比值为 `14.59%`。在全站总负荷达到峰值的那个小时，核心负荷为 `37.34 kW`，占当时总负荷的 `13.81%`。因此，UPS 按核心负荷峰值和恢复时间设计，而不是按核心负荷占全站电量比例直接缩放。

## 全容量搜索范围

不能把柴油机数量设成无限大后直接把所有整数逐一列出来，因为候选集合会变成无限集合，算法也就没有有限的全局搜索终点。当前程序不设置柴油机的物理上下限：它先评价一个可行参考方案，得到当前可行目标值 $J_{inc}$，然后对每种风电、光伏、电池、PCS 和 UPS 组合从 `0` 台开始枚举柴油机。若某个组合的投资成本已经满足 $C_{invest}\geq J_{inc}$，由于运行成本非负，该组合不可能改善目标值，搜索就停止扩展该组合。这是分支定界的成本停止条件，不是机组数量约束。

因此输出状态 `global_optimal_within_declared_synthetic_grid` 的含义是：在这套自动生成的离散容量水平、成本分支定界和 16 个训练场景内完成了全局搜索。它不是无限连续容量空间的全局最优，也不表示“11 台”是用户输入的机组上限。

## UPS 容量规则

当前示例声明柴油机最坏恢复窗口为 `8 h`，核心负荷功率留有 `1.5` 倍功率裕度。UPS 能量容量按“安装容量中真正可以放出的部分”计算：低风险时段至少保持 `60%` SOC，最低 SOC 为 `5%`，放电效率取 `98%`。

$$
E^{UPS}_{usable}=E^{UPS}_{nominal}\left(SOC^{reserve}_{low}-SOC_{min}\right)\eta_{UPS},
\\[2pt]
E^{UPS}_{nominal}\geq
\frac{P^{core}_{max}\times 8\text{ h}}
{\left(SOC^{reserve}_{low}-SOC_{min}\right)\eta_{UPS}},
\qquad
P^{UPS}_{min}=1.5P^{core}_{max}.
$$

本次合成数据的核心负荷峰值约为 `39.46 kW`，所以核心负荷需要的可用桥接电量约为 `315.69 kWh`，考虑 SOC 和效率后的 UPS 安装容量下限约为 `585.70 kWh`，功率下限约为 `59.19 kW`。候选档位中，`600 kWh / 100 kW` 是第一个同时满足两个下限的容量。这个规则是合成工程假设，用来体现“核心负荷不能停机，UPS 要覆盖柴油机恢复时间”。如果后续得到现场的核心负荷和柴油机恢复统计，应替换这些输入。

UPS 只给核心负荷使用。正常电网供电时，电网承担普通负荷，UPS 不会因为新能源出力不足而放电；UPS 可以用新能源富余电量或健康电网恢复到目标 SOC。天气预报进入高风险窗口时，SOC 目标从低风险的 `60%` 提高到 `90%`。设备随机故障不会被提前知道。

所有 PCS 和柴油机都标记为构网型。电网母线故障时，健康 PCS 和在线柴油机共同提供构网容量；如果主电网暂时无法建立，UPS 仍优先保证核心负荷。

## 储能 PCS 与复合极端场景

这里的 PCS 按储能 PCS 处理，不能在没有储能电池时单独建设。当前模型要求：只要 `PCS>0`，就必须有不小于 `1 h` PCS 额定功率的电池能量；例如 `200 kW` PCS 至少需要 `200 kWh` 电池。孤网时，PCS 只有在该小时实际输出非零有功功率时才计入构网功率。没有电池、没有可用电量或当小时没有 PCS 有功输出时，PCS 不计入构网支撑。

规划和验证场景中加入了明确的复合极端子场景：把合成暴风雪窗口与主电网母线断开、新能源母线断开同时强制重合，用于检查“暴风雪导致新能源减产，同时全网失电且新能源母线不可用”时核心负荷、刚性常规负荷和构网支撑是否仍满足约束。该子场景与普通联合随机场景分开统计。

## 本次全容量搜索结果

16 个训练场景中的最低费用方案为：

| 设备 | 容量 |
|---|---:|
| 风电 | 400 kW |
| 光伏 | 200 kW |
| 柴油机 | 2 × 100 kW |
| 普通电池 | 0 kWh |
| PCS | 200 kW，构网型 |
| UPS | 600 kWh / 100 kW |

该方案的训练目标值为约 `1,635,646` 元，其中投资成本为 `1,535,000` 元，16 个训练场景的平均运行成本为约 `100,646` 元。验证集沿用同一容量方案，投资成本不变，32 个验证场景的平均运行成本约为 `88,794` 元。

合成核心负荷峰值约为 `39.46 kW`，由 `8 h` 恢复窗口、SOC 可用比例和 `1.5` 倍功率裕度得到：

- 核心负荷需要的可用能量约 `315.69 kWh`；
- UPS 安装能量下限约 `585.70 kWh`；
- UPS 功率下限约 `59.19 kW`。

因此 `600 kWh / 100 kW` 是这次全容量搜索中训练样本成本最低的满足方案。此前报告中的 `500 kWh` 只按名义容量比较，没有扣除最低 SOC 和效率，已经被当前版本的容量校核纠正。这个结果只属于合成数据和当前容量候选，不能直接当作现场 UPS 采购值。

## 风险结果

这次为了在 `10000` 秒内完成全容量搜索，规划使用 `16` 个联合天气/故障训练场景，另用 `32` 个独立场景验证。当前结果为：

| 指标 | 训练 | 独立验证 |
|---|---:|---:|
| 核心负荷 $EENS$ | 0 kWh | 0 kWh |
| 刚性常规负荷 $EENS$ | 74.08 kWh | 47.85 kWh |
| 刚性常规负荷 $CVaR_{0.95}$ | 281.46 kWh | 255.20 kWh |
| 构网型 PCS/柴油机 | 全部启用 | 全部启用 |

核心负荷在 `16` 个训练场景和 `32` 个独立验证场景中均没有失供。刚性常规负荷的训练 $EENS=74.08$ kWh、验证 $EENS=47.85$ kWh，均低于当前 `100 kWh` 限值；训练和验证的 $CVaR_{0.95}$ 分别为 `281.46` kWh 和 `255.20` kWh，也低于 `1000 kWh` 限值。这个结果通过了当前独立验证，但场景仍为合成样本，不能替代现场数据校准。

按场景类别看，天气场景中刚性常规负荷 $EENS=0$；随机故障场景中 $EENS=93.11$ kWh、$CVaR_{0.95}=325.14$ kWh；联合天气/故障场景中 $EENS=63.14$ kWh、$CVaR_{0.95}=345.23$ kWh。说明当前刚性负荷风险主要来自偶发设备和母线故障，而不是单独的可预测极端天气窗口。

## 当前边界

本算例的气象、负荷分类、故障概率、恢复时间、核心负荷恢复窗口和成本都是模拟输入。`flex_shiftable_kw` 当前表示允许平移的调节容量包络，输出其调节电量；如果要对具体生产任务建模，还需要补充任务的最晚恢复时间、连续运行时间和移峰后的回补约束。
