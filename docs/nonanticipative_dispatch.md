# 事故调度的非预见性约束

全年大样本另提供 [非预见策略证据与独立验证接口](nonanticipative_certificates.md)，可以利用对未见历史也有定义的因果策略进行验证。以下限制针对原 `nonanticipative` 联合场景树接口本身；新证据接口不把验证集上的树重新优化当作验证。

本版本在 `run.sh` 的固定场景规划中实现联合场景树 UC。默认入口读取 `config/zhongshan_nonanticipative.toml`。已有显式历史配置未声明 `accident_dispatch` 时仍按完全预见口径运行，以便复现历史结果；可通过 `--dispatch-information nonanticipative` 显式切换。

工作区另有独立的 `run_certified.sh` 总体置信认证实现；本次修改没有将联合场景树策略当作其独立逐路径 Oracle。两种程序的信息结构和统计保证不能混用。

## 1. 信息时序

容量 $n$ 在事故发生前确定。每小时先观察当前天气状态、当前风光负荷因子及所有已安装模块的可用状态，再选择该小时出力、启停和充放电。基准全年风光负荷预测是公共输入；未来故障、维修和随机天气实现不可提前用于区分历史相同的场景。未安装模块的状态不进入可观察信息。

令 $o_{s,t}(n)$ 表示以上观测，历史为

$$H_{s,t}(n)=(o_{s,0}(n),\ldots,o_{s,t}(n)).$$

运行控制向量包含

$$y_{s,t}=(P^W,P^{PV},P^{DG},P^c,P^d,P^{shed},z,\{u_i,v_i,w_i\}_i)_{s,t}.$$

非预见性约束是

$$H_{s,t}(n)=H_{r,t}(n)\quad\Longrightarrow\quad y_{s,t}=y_{r,t}.$$

代码用“父历史编号 + 当前观测”构造信息节点，避免直接比较整段历史。曾经分叉的历史不会因为当前可用状态相同而重新合并。节点构造不读取未来观测或使用场景索引作为可观察信息。柴机故障可在当小时引发强制停机，机组可以在观察当前状态后作出反应；本版本没有额外一小时启机提前量。

## 2. 储能与物理约束

事故调度初始 SOC 在配置中固定，默认为 0.8；所有场景共享：

$$e_{s,0}=(SOC^{init}-SOC^{min})x_B.$$

不再允许针对不同事故选择不同的初始储能。沿用首尾库存约束 $e_{s,T}=e_{s,0}$、小时能量守恒、SOC 上下界、充放电互斥、柴油逐机最低出力及最小开停机时间。相同历史下的库存也检查一致性。标称经济主问题沿用原有自由、周期初始库存，这与事故调度的固定初始库存是两种明确的边界条件；当前不将事故初始库存绑定到标称年内某个随机事故发生时刻。

## 3. EENS/CVaR 必须属于同一套策略

原逐场景最优值 $Q_s=\min_{y_s}\sum_t P^{shed}_{s,t}\Delta t$ 不能再独立计算。现在令

$$q_s(y)=\sum_tP^{shed}_{s,t}\Delta t,$$

在联合物理约束及非预见约束下，同时要求

$$\sum_s\pi_s q_s(y)\le\bar E,$$

$$\eta+\frac{1}{1-\alpha}\sum_s\pi_s\xi_s\le\bar C,
\qquad \xi_s\ge q_s(y)-\eta,\quad \xi_s\ge0.$$

求解时先最小化共同超限量 $v\ge0$，将右端分别改为 $\bar E+v$、$\bar C+v$。当得到可行双风险策略后，在维持已取得超限量上界的条件下再最小化 EENS。这样不会因只优化 EENS 而忽略另一套可以满足 CVaR 的策略，也避免纯可行性求解输出任意失供值。

最终每个 $q_s$ 是同一策略在该场景上的损失，不是该路径独立调度的最小值。规划样本选择过策略，因此不把这些损失当作固定策略下的独立样本来报告均值标准误。输出的 `standard_error_kwh` 留空并说明原因。

## 4. cut 的依据

新增容量可保持闲置；增加电池后额外初始库存可始终保留。已安装模块更多时，观测历史分组只会细化，较大容量仍可以忽略新增模块信息并沿用旧策略。因此有限场景树上双风险可行容量仍然向上封闭，原容量下闭区域 cut 可以保留。

只有最小共同超限量的全局下界严格超过数值容差，才判定不存在满足双风险约束的策略并生成 cut。某套超时可行策略失供很大，不能用来证明容量失败；若未取得有效失败下界则返回求解未决错误。超限量为零的合法联合策略足以证明样本可行。逐场景完全预见零失供证书、独立场景提前停止以及逐路径最优损失缓存不用于新接口的接受判定。

失败策略的 EENS/CVaR 数字描述该策略；失败证明来自联合超限量下界，不表示任何其他策略的每个风险分量都至少同样高。该依据保存在 `failure_proof` 与 `joint_violation_bound_kwh`。

## 5. 范围与计算规模

这是有限经验场景树上的严格非预见约束。若某个历史在树中只有一条后续路径，该节点的经验条件分布就退化为确定分支；加入等历史约束不会自动使少量独立年度轨迹变成充分分叉的多阶段情景树。用于研究真实运行策略时仍需设计足够的条件分支或独立的因果控制器。

策略仅对树内历史定义。不能在新的验证样本上重新优化另一棵树，再标成原策略的独立验证。因此本模式请求 `validation_samples > 0` 会在生成场景前报清楚的错误。真实独立验证还需要给未见历史定义可执行控制策略；本次没有声称完成该部分，也没有提供总体置信认证。

当前采用每场景一套运行变量和信息节点等式，规模随 $N T$ 增长，默认资源上限为 200000 个场景小时。历史 20000 × 8760 相当于 175200000 个场景小时，不能沿用逐路径程序的运行时间预期。超限会停止并给出明确说明；程序不会自动降样本或退回完全预见。

新配置显式使用 16 个年度场景作为联合模型原型，保留文献参照故障参数及风、光各 10 个模块上限。16 是新的原型配置，不能替代之前的 20000/100000 实验。限值仍按选定时域计量，短时域测试不外推全年。

## 6. 运行与证据

```bash
# 中山 24 小时、8 场景端到端检查
./run.sh plan --hours 24 --samples 8 --solver-config config/solver_3600_1pct.toml

# 新配置：全年 16 场景的联合调度原型
./run.sh plan --config config/zhongshan_nonanticipative.toml --solver-config config/solver_3600_1pct.toml

# 显式指定其他配置时切换模式，并声明本次只做有限树内规划
./run.sh plan --config config/zhongshan_literature_2000.toml \
  --dispatch-information nonanticipative --hours 24 --samples 8 --validation-samples 0
```

`accident_policy.npz` 保存每个场景的完整出力、电量、逐机启停和信息节点；摘要写入信息结构、固定初始 SOC、联合超限量界、策略含义和独立非预见性审计。固定容量评价命令同样支持本模式。标称 `baseline` 与历史 `validate-small` 仍按原经济/历史测试口径运行；新的非预见穷举验证位于 `tests/test_nonanticipative.py`。

测试包括：未来负荷分叉不能改变早期启机、历史分叉后不能重新合并、未安装设备不能泄露信息、固定共同初始库存、故意篡改策略时审计失败，以及 48 点穷举对比规划 cut。两分支反例中完全预见 EENS 为 0.5，联合非预见 EENS 为 1.0，体现未来信息确实受到约束。
