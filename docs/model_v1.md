# 模型与算法口径

## 1. 容量及标称主问题

令 $J=\{W,PV,DG,B,PCS\}$。每个容量都模块化：

$$n_j\in\{\underline n_j,\ldots,\overline n_j\},\qquad x_j=u_j n_j.$$

`battery_energy` 表示额定电量 $E_B$，单位 kWh；其他容量单位 kW。代码中各模块独立取整数，不把 PCS 功率与电池电量强行捆绑。

主问题在标称风光/负荷轨迹上，最小化时域内年均资本成本与燃料成本：

$$\min\ \frac{T\Delta t}{8760}\sum_j \frac{c_j u_j}{L_j}n_j
+c_{fuel}\sum_{t=0}^{T-1}P_{DG,t}\Delta t.$$

这里 $c_{fuel}$ 为柴油单价除以燃油效率，未计折现、残值、启停和故障场景中的燃料成本；这与指导中的“经济主问题 + 外部可靠性约束”一致。8760 小时运行时资本项恰好为年度平均投资。

每小时运行变量为风、光、柴油出力，充电功率 $P^c_t$、放电功率 $P^d_t$、失供功率 $P^{shed}_t$ 和可用储能电量 $e_t$。主问题固定 $P^{shed}_t=0$。

$$P_{W,t}+P_{PV,t}+P_{DG,t}+P^d_t+P^{shed}_t=L_t+P^c_t.$$

$$0\le P_{W,t}\le f_{W,t}S_W,\quad
0\le P_{PV,t}\le f_{PV,t}S_{PV},\quad
0\le P_{DG,t}\le S_{DG}.$$

风光出力可以主动减少，不要求所有可发电量都进入平衡式。柴油调度在本阶段没有必须开机、最小出力、最小开停机时间约束。

$$P^c_t\ge0,\ P^d_t\ge0,\quad P^c_t+P^d_t\le S_{PCS}.$$

储能以最低 SOC 以上的可用电量建模：

$$0\le e_t\le (SOC_{max}-SOC_{min})E_B,\quad t=0,\ldots,T,$$

$$e_{t+1}=e_t+\eta P^c_t\Delta t-\frac{P^d_t\Delta t}{\eta},\qquad e_T=e_0.$$

初始 $e_0$ 由模型选择。实际电量为 $E_t=e_t+SOC_{min}E_B$。这种偏移形式避免把“容量增加造成 SOC 下界增加”误认为运行域收缩，也让单调性证明直接成立。时域首尾相等避免靠免费消耗初始库存供电。短时域也采用时域首尾相等，不替代原时域中间任意片段的实际初末 SOC 条件。

充放电使用连续变量和共享 PCS 功率约束，没有小时级充放电互斥二进制。因此这是一阶调度 LP 口径；在免费弃电、无必须运行机组、无补贴套利和正损耗的设定下，不需要靠同时充放电改善最小失供目标。不要把输出任意退化最优调度解释为实际控制策略。后续若添加必须运行、负电价或复杂电池寿命，应重新审查此口径。

## 2. 固定故障场景

在一次规划前，按每类设备的容量上界生成全部潜在模块的可用性：

$$a_{j,i,t,s}\in\{0,1\},\quad i=1,\ldots,\overline n_j.$$

候选安装 $n_j$ 个模块时，始终使用同一组前 $n_j$ 条轨迹：

$$A_{j,t,s}(n_j)=u_j\sum_{i=1}^{n_j}a_{j,i,t,s}.$$

因此同一 $\omega_s$ 下，容量增加不会使原有模块变差，也不会改变天气、负荷和其他模块的故障史。每个随机流由种子、组件、样本和模块序号确定；增加样本数或最大模块数不会重抽已有轨迹。NPZ 存档和 SHA256 记录实际用于评价的数组。

基线对风机、光伏、柴油和 PCS 建立故障/维修链。电池电芯保持完好，故障 PCS 只降低可用充放电功率，不销毁已存电量；PCS 维修后可重新访问这部分电量。当前代码明确拒绝电芯故障配置，避免把能量状态随可用容量跳变的模型混入基线。

离散小时转移使用：

$$p^{fail}_w=1-\exp(-\lambda_w\Delta t),\qquad
p^{repair}_w=1-\exp[-\Delta t/(MTTR\,m_w)].$$

若模块当前完好，按 $p^{fail}_w$ 转为故障；若当前故障，按 $p^{repair}_w$ 返回完好。同一时间步至多一次状态改变，不建模小时内的事件顺序。`mean_repair_hours` 控制连续指数分布对应的参数，离散后的平均故障持续步数为 $1/p^{repair}_w$。

初始故障概率采用当前天气下离散链的平稳值：

$$\Pr(a_0=0\mid w_0)=\frac{p^{fail}_{w_0}}{p^{fail}_{w_0}+p^{repair}_{w_0}}.$$

默认全部处于 NORMAL。可选气候模块产生公共 NORMAL/EXTREME 二状态链，条件化故障/维修率，也可设置极端状态的风、光、负荷乘数。气候条件下上述初始分布是条件初始化约定，并非联合天气—设备链的精确平稳分布；未声称用实测气候校准。气候影响仅通过 `Scenario` 传入运行模型，cut 与主问题不变。

## 3. 可靠性 Oracle

Oracle 是“固定容量 → 多场景运行优化 → 指标”的软件接口。内部需要优化每个场景的运行 LP；它自身不搜索容量。

$$Q_s(x)=\min\sum_t P^{shed}_{t,s}\Delta t,$$

$$0\le P^{shed}_{t,s}\le L_{t,s}.$$

用 $A_{DG,t,s}$、$A_{PCS,t,s}$ 代替相应容量上界，用模块可用风光出力乘天气修正系数代替标称风光上界。储能仍沿整段时域连续联接，不做逐小时独立 dispatch。

这是已知整个场景后的**完全预见最小失供**，允许针对场景选择运行和首尾相等的初始电量。它是容量充分性规划的理想调度基准，通常比因果在线调度乐观；当前不包含跨场景非预见性、维修队伍、燃料运输约束或实际控制器。

同一 Oracle 复用一个 LP 并更新 RHS，重复容量直接读取缓存。必须得到 Gurobi `OPTIMAL` 才接受 $Q_s$；时限内的可行失供值只是最小失供的上界，不能据此证明不可靠并生成 cut。

## 4. EENS 和 CVaR

$$\widehat{EENS}(x)=\sum_s\pi_sQ_s(x),\quad \pi_s>0,\quad\sum_s\pi_s=1.$$

默认 Monte Carlo 样本等权，精确小算例支持不等权。

$$\widehat{CVaR}_\alpha(x)=\min_\eta\left[\eta+\frac{1}{1-\alpha}\sum_s\pi_s(Q_s(x)-\eta)_+\right].$$

实现直接按失供电量降序累计最坏的 $1-\alpha$ 概率质量，对边界场景按所需部分概率质量加权。例如损失 `[0,0,0,10,100]` 等权、$\alpha=0.75$ 时 CVaR 为 82，而不是尾部切片均值 55。

默认判定：$\widehat{EENS}\le\overline E+\epsilon$。配置 CVaR 限值后还要求 $\widehat{CVaR}\le\overline C+\epsilon$。$\epsilon$ 是数值比较容差，不是统计置信区间。短时域指标始终为该时域 kWh；不乘 `8760/T` 外推全年。

## 5. 单调可靠性 cut

给定相同场景，当 $n'\ge n$ 逐分量成立时，可用发电/PCS 上界和可用储能上界均不减。较大容量可沿用较小容量的全部运行变量，所以：

$$Q_s(n')\le Q_s(n)\quad\forall s.$$

EENS 和 CVaR 对每个场景损失都单调不减，因此不可靠点 $n^k$ 的整个下闭区域 $\{n:n\le n^k\}$ 均不可靠。

所需 cut 为：

$$\bigvee_{j:n_j^k<\overline n_j}n_j\ge n_j^k+1.$$

代码为每个可增加分量添加二进制 $z_{kj}$，用 Gurobi indicator 表达：

$$z_{kj}=1\Rightarrow n_j\ge n_j^k+1,\qquad\sum_j z_{kj}\ge1.$$

五个容量维度都参与。达到上界的分量不再进入析取；所有分量均达上界时，cut 为 $0\ge1$，从而正确判定该有限容量域不可行。单向 indicator 已足以精确表达这个存在性析取，不要求双向等价。

`--lift-cuts` 可逐坐标二分增加失败点：只有 Oracle 实际评价后仍失败的点才用作更大 cut 的顶点。通过评价的探测点不生成 cut。默认直接使用当前失败候选，以保持基线算法简单。

## 6. 停止、最优性与独立验证

每轮解主问题，评价候选；不满足指标则加 cut。容量域有限，每条 cut 排除至少一个此前未排除的失败点，精确求解时在有限步内得到样本内最优方案或证明有限域不可行。用户设置的迭代上限可以提前终止，程序此时报告 `iteration_limit`，不把最后的失败容量当作最终方案。

所有 cut 都只排除固定样本不可行容量，因此主问题仍是原样本约束规划的外松弛。主问题有效成本下界 $LB$ 和通过 Oracle 的候选成本 $UB$ 给出：

$$gap=\frac{\max(0,UB-LB)}{\max(|UB|,10^{-10})}.$$

`sample_optimal_within_gap` 只证明这一**固定样本、有限模块网格、简化运行模型**的成本 gap，不证明容量连续域最优，更不证明总体可靠性。主问题超时但有候选时可继续做可靠性评价，仍按真实下界报告 gap。

独立验证使用不同种子和相同场景生成规律，结果不回流到规划 cut。规划样本通过而独立样本失败时，程序保留两者并返回退出码 3。标准误仅作为等权独立样本 EENS 的描述统计；稀有事件中全零样本的标准误为零并不意味着没有风险。当前没有 CVaR 置信带、自适应样本停止或多次检验校正。

## 7. 已实现和后续研究边界

已实现无故障容量 MILP、连续时序运行 LP、可维修模块故障场景、EENS/CVaR、固定样本 Oracle、单调 cut、可选 cut 提升、小系统完整穷举、独立样本检查及气候条件场景接口。

尚未实现 Wu 2021 的特定拟合公式对照、气候/维修参数估计、电芯级故障与库存耦合、因果调度、自适应置信判定。它们需要明确数据和数学口径后逐项加入，不应从当前有限算例的通过推断论文层面的算法优势。
