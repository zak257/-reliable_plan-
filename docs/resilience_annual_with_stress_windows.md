# 8760小时容量规划与72小时韧性子场景

规划主时域为8760小时，72小时仅用于嵌入事故前准备、事故供电和恢复过程。风、光、柴油机、普通电池、储能PCS、UPS能量和UPS功率的整数模块数量，由同一个Gurobi MILP统一优化。

全年版入口为 `python -m scripts.run_resilience_milp`，默认使用 `--mode annual --hours 8760`。独立72小时演示需要显式选择 `--mode demo --hours 72`，其容量结果不作为全年规划结果。

## 全年与子场景怎样连接

模型建立一条8760小时的正常运行轨迹，并在全年四个时段加入72小时事故分支。正常轨迹中每小时都计算风光利用、柴油机启停和燃油、储能充放电、可调负荷及实际构网功率，全年电池电量连续演变。全年任何时刻发生的常规负荷实际失供都计入费用和风险，包括事故窗口之外的失供；合法负荷调节不算失供。

每个子场景与全年轨迹共享相同装机容量。子场景边界不是额外赠送的一份电量：

$$
E^{B}_{j,s,0}=E^{B}_{\tau_j},\qquad
E^{U}_{j,s,0}=E^{U}_{\tau_j}.
$$

柴发起始在线状态、人员准备进度、机舱温度，以及尚未完成的可平移负荷，也继承全年对应时刻的变量。故障前已经发生的启动和准备申请会继续影响子场景。

子场景结束时，电池与UPS电量、已安装柴发温度、启停和维修等状态须恢复到全年对应时刻的公共轨迹。跨出窗口的可平移负荷继续使用全年未来服务变量。因此不能靠耗尽电池后结束子场景，也不能让跨边界的待完成负荷消失。

这是明确的恢复要求：当前72小时窗口必须足以完成恢复。若以后研究持续更久的灾害，需要延长窗口；不能在恢复未完成时直接重置设备状态。

## 当前模拟场景

当前沿用用户授权生成的模拟全年负荷与气象曲线，未将其标为中山站实测数据。为形成四个季节的压力窗口，选择全年从第0天计数的第34、104、234、314天为窗口起点，对应小时816、2496、5616、7536。

每个窗口有16个条件分支，共64个分支记录：正常/暴风雪两种天气与八种故障条件组合。正常且无故障的分支直接共用全年轨迹，因此实际为一条全年轨迹加60个局部运行分支。

| 条件 | 当前合成设置 |
|---|---|
| 暴风雪 | 窗口第24至53小时，共30小时；气温为$-12\,^{\circ}\mathrm{C}$，风光出力系数分别乘0.35、0.65 |
| 新能源母线断开 | 第36小时发生；正常天气8小时、暴风雪12小时，风光送出功率均为零 |
| 主母线失电 | 第36小时失电1小时，独立UPS支路保障核心负荷 |
| PCS、UPS故障 | 分别持续4小时 |
| 柴发运行故障 | 只有机组此前实际在线，潜在故障才暴露 |
| 柴发启动失败 | 只有实际尝试启动时才暴露 |
| 柴发维修 | 当前合成设置为6小时 |
| 复合场景 | 暴风雪与新能源母线断开；全主母线失电仍单列 |

窗口内天气权重为正常0.8、风雪0.2；八类条件权重为无故障0.60、新能源母线0.10、主母线0.10、复合0.08、PCS 0.03、UPS 0.03、柴发运行故障0.04、启动失败0.02。这些是每个风险窗口内的条件权重，并非直接测得的年故障率。同一年可以在多个窗口内发生事件。

当前孤网条件下，“新能源母线故障”和“复合”中的同天气分支可能等价，其权重仍分别保留。窗口覆盖的是明确选定的四组季节压力条件，不代表已经穷尽全年每小时所有可能的故障。

## 只提前一天知道天气

窗口第0小时发布次日是否极端天气的信号，风雪在第24小时才开始。模型可以在收到信号后给普通电池充电、提前安排人员及预热柴发；更早时刻的设备状态与全年轨迹共用。

设备故障不提前揭示。相同已观测信息下，各分支的操作必须相同。柴发未安装、未运行或未尝试启动时，未暴露的潜在故障不会使分支提前分开。全年背景负荷与风光基准曲线仍是给定研究输入，当前信息约束针对极端天气信号和故障分支，并未建立所有气象预测误差的全年随机过程。

## 全年费用，避免重复计费

设$\mathcal T_0$为四个窗口以外的全年小时，$C^0_t$为正常运行费用，$C_{j,s}$为第$j$个72小时分支的运行与失供损失费用，$p_{j,s}$为该窗口内分支的条件权重。目标为：

$$
\min\ C_{\mathrm{inv}}+
\sum_{t\in\mathcal T_0} C^0_t+
\sum_j\sum_s p_{j,s}C_{j,s}.
$$

每个窗口的期望运行费用替代该时段的正常费用，全年8760小时恰好计一次；不是在全年费用上再完整加一遍72小时正常运行费用。跨窗口可平移负荷按实际服务时刻计调节费用，未完成任务按到期时刻计损失。

当前财务口径沿用设备投资加全年期望运行费用。尚未加入设备寿命、折现率和资本年化；因此目标不能称为“年化总成本”。与此前投资加72小时运行费相比，本版已正确计入一整年的运行经济性。

## 全年韧性指标

所有正常与故障分支的核心负荷均要求无失供。UPS仅应急供应核心支路；启动UPS对应的常规负荷切除计入损失。合法中断调节和按期完成的用电平移不计失供。

设$Q_0$为四个风险窗口以外的正常轨迹失供，全年期望失供为它与各风险窗口期望失供之和：

$$
\mathrm{EENS}_{\mathrm{year}}=Q_0+\sum_j\sum_s p_{j,s}Q_{j,s}\le100\ \mathrm{kWh}.
$$

全年尾部风险采用保守约束：

$$
\mathrm{CVaR}_{0.95}\!\left(Q_0+\sum_j Q_j\right)
\le Q_0+\sum_j\mathrm{CVaR}_{0.95}(Q_j)
\le1000\ \mathrm{kWh}.
$$

这是利用CVaR的次可加性得到的全年风险上界。报告字段明确写为 `cvar_upper_bound_kwh`，不能把它当作完整全年联合分布的精确CVaR。EENS按各窗口相加，不能把四组权重重新归一化后平均，否则会低估全年风险。阈值和概率均为当前研究假设。

## 运行与验证

```bash
/home/yzk/cap_plan/venv/bin/python -m scripts.run_resilience_milp \
  --mode annual --hours 8760 \
  --time-limit-seconds 10000 --mip-gap 0.001 --threads 4 \
  --output reports/resilience_milp_annual_8760_run
```

七类容量全部为整数模块变量，模块规格和应急UPS规则保持此前确认值。所有约束统一由Gurobi求解。时间预算包括建模和求解，结果审计与导出另有开销；超时时如有可行解，就报告可行容量及其最优性差距，不能直接称为全局最优。

新增测试检查全年费用替换、年度风险累加、实际电量继承、跨窗口柔性任务守恒、恢复衔接及故障前操作一致性。完整测试命令为：

```bash
/home/yzk/cap_plan/venv/bin/python -m unittest discover -s resilience_tests -v
```

本轮59项测试全部通过，其中8项专门检查年度连接。另完成120小时背景轨迹加一个72小时窗口、16个分支的孤网集成验证，安装了非零风电，审计最大数值残差约为$5.91\times10^{-10}$。该固定容量接入验证保存于 `reports/resilience_annual_linked_window_final_verification/`，仅用于验证模型接入，不作为全年容量结论。

正式8760小时全容量运行目录为 `reports/resilience_milp_annual_8760_20260923T082231Z/`；其 `run_status.json` 记录运行状态，完成后 `summary.json` 给出本次结果。

输出包括全年输入、窗口清单、逐时运行CSV与NPZ、费用与容量汇总、Gurobi日志、模型、解和物理/信息审计。求解器的最优性结论仅针对上述有限场景及恢复要求，不代表对未建模天气或故障的全年可靠性证明。
